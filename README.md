## 📖 프로젝트 소개

마블 영화(MCU)에 대해 **답이 문서 한 건에 다 들어 있지 않은 질문**에 답하는
에이전트입니다. 예를 들어 "인피니티 스톤을 둘러싼 주요 사건들은 무엇이고, 각각의
원인은 무엇인가?" 같은 질문입니다. 스톤은 여섯 개이고 등장하는 영화도 회수되는
영화도 제각각이라, 문서 하나를 읽어서는 절반도 쓸 수 없습니다.

가장 단순한 방법은 자료를 전부 AI에게 주는 것입니다. 그런데 그게 **물리적으로
안 됩니다.** 모은 자료가 **51건 · 1,543,251자**인데, AI가 한 번에 볼 수 있는 양은
약 51만 자(gpt-4o-mini, 128k 토큰)입니다. **자료가 약 3배 더 많습니다.**

그래서 **나눠서 읽고, 나눠서 쓰고, 이어 붙이는** 구조를 만들었습니다.
이 프로젝트는 그 분업을 **신문사 편집국**에 비유합니다.

```
① 기획 → ② 배정 → 🔏 결재 → ③ 조사 ×5 → ④ 점검 →(↺ ②로)→ ⑤ 종합 → ⑥ 평가
편집장    편집장     당신      기자 5명 동시   편집장              편집장     계량 담당
```

여기서 중요한 규칙이 하나 있습니다. **기자가 읽은 원문은 기자 밖으로 나오지
않습니다.** 편집장은 기자가 쓴 원고만 받지 원문을 다시 읽지 않습니다. 실제로
편집장이 본 글자는 팀 전체가 읽은 글자의 **5.7%뿐**입니다.

그리고 ② 배정이 끝나면 **사람이 한 번 끼어듭니다.** 목차와 배정을 보고 승인하거나
반려합니다. 배정이 틀리면 보고서는 멀쩡해 보이기 때문에, 사람이 되돌릴 수 있는
마지막 지점이 여기입니다.

가장 공들인 부분은 **「못 믿을 숫자」를 못 믿게 만드는 장치**입니다. 반복 측정을
돌리기 **전에** 판정 규칙을 커밋하고, 집계 도구가 그 규칙을 코드로 돌립니다.
3회가 안 차면 **스스로 판정을 거부합니다.** 이 장치들이 실제로 잘못된 결론 두 개를
막았습니다.

설계 근거 · 측정 결과 · 실패 분석 · 한계는 **[REPORT.md](REPORT.md)** 에 있습니다.

## ✨ 주요 기능

- [x] 위키백과 자동 수집으로 코퍼스 구축 (51건 · 154만 자 · 문서 간 링크 포함)
- [x] LangGraph 6단계 파이프라인 — 기획 → 배정 → 조사 ×5 → 점검 → 종합 → 평가
- [x] **사람 결재 게이트** — 배정이 끝나면 멈추고, 반려하면 목차부터 다시 짭니다
- [x] 컨텍스트 격리 — 원문은 기자 안에서만 소비하고, 그 비율을 매번 측정합니다
- [x] 정답표·판정 모델 없이 재는 **지표 9개** + 0이어야 하는 「그물」 2개
- [x] 절제 실험(장치 끄기) · 반복 측정 · **혼자 하는 비교군**까지 3중 검증
- [x] 사전등록 — 판정 규칙을 먼저 커밋하고, 3회가 안 차면 판정 거부
- [x] 아이소메트릭 사무실 데모 — 의존성 0 Canvas, **API 키 없이 기록 34편 재생**

## 🚀 시작하기 (Getting Started)

### Prerequisites (사전 준비)

- **Python 3.10 이상** (개발·테스트는 3.14 기준)
- **OpenAI API 키** — 직접 실행할 때만 필요합니다
- 화면만 볼 거라면 **아무것도 설치하지 않아도 됩니다** (표준 라이브러리만 씁니다)

### Installation (설치 방법)

```bash
# 레포지토리 클론
git clone https://github.com/elfinnani-byte/mcu-deep-research.git
cd mcu-deep-research

# 가상환경 생성 및 활성화
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS · Linux

# 패키지 설치
pip install -r requirements.txt
```

`server/.env` 파일을 만들고 API 키를 넣습니다 (`server/.env.example` 참고):

```
OPENAI_API_KEY=sk-...
```

`.env` 는 `.gitignore` 에 걸려 있어 커밋되지 않습니다.

## 💡 사용법 (Usage)

### 화면 보기 — 키 없이

실행 기록 34편이 저장소에 들어 있으므로 **설치 없이** 바로 볼 수 있습니다.

```bash
cd web && python serve.py      # http://127.0.0.1:8765
```

정적 파일만 있으면 되므로 아무 웹서버나 됩니다. `serve.py` 는 캐시를 끄고,
배포판의 서버리스 함수(`api/*.py`)를 **같은 코드로** 로컬에서도 돌립니다.

화면은 셋으로 나뉩니다.

| 탭 | |
|---|---|
| **재생** | 기록 34편을 **질문 × 설정** 두 축으로 골라 대조군끼리 견줍니다 |
| **라이브** | 본인 키를 넣고 질문을 직접 돌립니다. 키는 **이 브라우저에만** 저장됩니다 |
| **설정** | API 키 입력·삭제 |

주소로도 부를 수 있습니다 — `?replay=` `?tab=` `?speed=` `?auto=0` `?report=1`.
예: [`?replay=q4-역할끔&report=1`](https://mcu-deep-research.vercel.app/?replay=q4-%EC%97%AD%ED%95%A0%EB%81%94&report=1)

### 직접 돌리기 — 키 필요

```bash
python -m server.pipeline "질문"        # 1회 약 $0.025 · 1~3분
python -u server/baseline.py q1        # 혼자 하는 비교군
python -u server/batch.py              # 절제 실험 20편 (약 $0.50)
python -u server/repeat.py             # 사전등록한 반복 측정
```

### 검사·집계 도구

```bash
python tools/질문검사.py     # 질문 세트가 코퍼스·기록과 어긋나는지
python tools/녹화목록.py     # 기록 목록을 폴더에서 다시 만든다
python tools/반복분석.py     # 반복 측정 집계 + 사전등록한 판정
python tools/팀대혼자.py     # 팀 vs 혼자 (차이 옆에 흔들림 폭을 같이 찍습니다)
python tools/배포검증.py     # 배포판이 살아 있는지 (정적 + 서버리스 함수)
```

### 파일 구조

```
corpus.json                자료 51건 + 링크. 손으로 고치지 않고 build_corpus.py 로 재생성
build_corpus.py            위키백과 수집 스크립트
data/questions.json        질문 8건 — 유형과 「왜 나눌 만한가」. 질문은 여기 한 곳에만

server/pipeline.py         파이프라인 6단계 + 지표 (866줄)
server/llm.py              모델 호출 · 계량기 · 키 주입
server/record.py           실행을 web/replay/*.json 으로 녹화
server/batch.py            절제 실험 20편
server/repeat.py           사전등록한 반복 측정
server/baseline.py         혼자 하는 비교군 (예산을 팀 실측에 맞춥니다)

api/plan.py                서버리스 함수 — ①② 를 돌리고 결재 앞에서 멈춤
api/run.py                 서버리스 함수 — ③부터 끝까지 SSE 로 흘림
api/_common.py             입력 검증 · 키 가리기 · 오류 분류

web/index.html, web/js/    화면 전부. js/config.js 가 모든 수치의 단일 출처
web/serve.py               개발 서버 (캐시 끔 + api/ 를 같은 코드로 실행)
web/replay/                실행 기록 34편 — 손으로 만들지 않습니다
runs/                      혼자 하는 비교군 5편

tools/                     검사·집계 도구 5개
docs/                      설계 · 실험 · 실패 기록
```

## 🛠 기술 Stack

- **파이프라인**: LangGraph, LangChain (OpenAI gpt-4o-mini)
- **배포**: Vercel 서버리스 함수(Python) + 정적 호스팅
- **화면**: 의존성 **0** — 순수 Canvas 2D · ES 모듈. 빌드 단계가 없습니다
- **측정**: 표준 라이브러리만. 판정 모델을 쓰지 않고 **코드가 문자열로 셉니다**

## 📊 측정 결과 요약

장치를 하나씩 꺼 보고 무엇이 실제로 값을 하는지 쟀습니다.
정답표도 판정 모델도 쓰지 않았습니다.

| 물음 | 답 |
|---|---|
| 기자마다 읽을 구역을 나눠 주면 나아지나 | ✅ **나아집니다.** 끄면 5/5 질문에서 겹쳐 읽기가 늘었습니다 |
| 기자에게 역할(명찰)을 주면 나아지나 | ⏳ **못 정했습니다.** 차이(12~13%p)가 흔들림 폭(14.3%p)보다 작습니다 |
| 빈 절을 다시 내보내면 나아지나 | ⚠ **못 가렸습니다.** 방향이 질문마다 뒤집힙니다 |
| 다섯이 나눠 하면 혼자보다 나은가 | ⚠ **못 가렸습니다.** 역시 질문마다 뒤집힙니다 |

## 한계

- **나눠서 하는 게 혼자보다 나은지 못 가렸습니다.** 이 프로젝트의 전제를 검증도
  반증도 못 했습니다. 반복 측정을 q2·q5 두 질문에만 했고, 비교군도 칸당 1회뿐입니다.
- **자료의 제목이 51건 중 28건 내용을 잘못 말합니다.** 수집 스크립트가 문서를
  소제목에서 자르면서 그 뒤 내용을 전부 한 조각에 넣었기 때문입니다. 고치려면 자료를
  다시 만들어야 하고, 그러면 기록 34편이 전부 무효가 되어 이번에는 하지 않았습니다.
- **다섯 번째 절이 늘 빕니다.** 배정이 앞 네 절에 알맹이를 다 주고 마지막에 남은 것을
  줍니다. 절 수를 질문에 맞춰 정해야 합니다.
- **「인용이 엉뚱한 곳에 붙었나」는 인용 문장의 33%만 판정합니다.** 본문이 한국어고
  자료가 영문이라 맞댈 단서가 없는 문장이 많습니다.
- **진짜 키로 라이브를 끝까지 돌려본 적이 없습니다.** 가짜 모델로 전 구간이 흐르는
  것과, 잘못된 키 처리는 확인했습니다.

전체 목록과 각각의 근거는 [REPORT.md](REPORT.md) 10장에 있습니다.

## 🤝 기여하기 (Contributing)

개인 학습 과제로 만든 프로젝트지만, 개선 제안이나 버그 리포트는 언제든 환영합니다.

1. 이 레포지토리를 Fork 합니다.
2. 새 브랜치를 생성합니다 (`git checkout -b feature/amazing-feature`).
3. 변경사항을 Commit 합니다 (`git commit -m 'Add some amazing feature'`).
4. 브랜치에 Push 합니다 (`git push origin feature/amazing-feature`).
5. Pull Request를 오픈합니다.

고치실 때 두 가지만 지켜 주세요.

- `corpus.json` 과 `web/replay/*.json` 은 **손으로 고치지 않습니다.** 앞은
  `build_corpus.py` 로 재생성하고, 뒤는 실제 실행 기록입니다.
- 키를 커밋하지 않습니다. `server/.env` 는 `.gitignore` 에 있습니다.
