#### 두 번째 원고 — 결정하지 않고 지나온 자리

명세 원문: *"무조건 덮어쓰면 **인용을 빠뜨린 원고가 멀쩡한 원고를 지웁니다.**"*

`server/pipeline.py:238` `절모음()` 은 같은 절이 두 번 올라오면 **마지막 것만** 남긴다.
지금까지 안 물린 이유는 실측으로 분명하다.

```
재위임으로 두 번 올라온 절: 3개 (녹화 22편 전체)
  q1-반려   1절  인용 0 ↑ 1    자수 287 → 488
  q4-기본   1절  인용 0 → 0    자수  68 → 426
  q4-역할끔  1절  인용 0 → 0    자수  56 → 397
```

**세 건 모두 1바퀴 인용이 0곳이라 잃을 것이 없었다.**
그런데 `인용0곳점검`(커밋 `fda1a90`)이 재위임 대상을 **3건 → 최대 21건**으로 늘린다.
이제는 「더 나쁜 2번째가 멀쩡한 1번째를 지우는」 일이 실제로 생길 수 있다.

#### 정한 것 — 「인용이 줄면 1바퀴를 지킨다」

재위임은 **빈 칸을 메우라고** 보내는 것이지 다시 쓰라고 보내는 것이 아니다.
2바퀴 기자는 1바퀴 메모를 물려받아 더 많은 자료로 쓰므로 보통 더 낫지만,
그것은 **보통**이지 **언제나**가 아니다. 더 나빠진 한 번에 멀쩡한 원고를 잃는 쪽이,
더 나아진 경우를 놓치는 쪽보다 나쁘다 — **잃은 것은 화면에도 지표에도 안 보이기 때문이다.**

읽은 기록은 언제나 나중 것을 쓴다(2바퀴가 1바퀴의 상위집합이다). 원고를 안 썼다고
읽은 것이 안 읽은 것이 되지는 않는다.

가짜 모델로 확인했다 — 1바퀴 인용 8곳 · 2바퀴 0곳인 절을 만들어 놓고:

| | 지킨다(기본) | 덮어쓴다 |
|---|---:|---:|
| 최종 인용 수 | **16** | 8 |
| 인용 0곳 절 | **0** | 1 |
| 근거율 | **100%** | 50% |

껐다 켤 수 있게 뒀다(`원고지키기`) — 이 결정 자체가 값을 하는지 나중에 재려는 것이다.
