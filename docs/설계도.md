## 0. 한 장 요약

브라우저 하나로 도는 **아이소메트릭 사무실**이다. 6노드 딥리서치 파이프라인이 실제로 돈 기록을
재생하면, 편집장 한 명이 기자 다섯을 회의에 불러 업무를 나누고 각자 서고로 흩어져 읽고
돌아와 보고한다. 서버도 빌드도 없다 — 정적 파일 + 방문자 본인 키(BYOK).

```
Source ──> EventQueue ──> Choreographer ──> World ──> Renderer
(기록|라이브)  (배속·hold)     (이벤트→상태)    (상태만)   (캔버스)
                                   │
                                   └─> script.js (자막·대사)   ui.js (패널)
```

**파이프라인은 파이썬 하나뿐이다** (`server/pipeline.py`). 라이브도 그것을 쓴다 —
브라우저가 `/api/plan` · `/api/run` 을 부른다.

> 예전에는 자바스크립트로 한 벌 더 있었다(`web/js/pipeline.js`, 344줄). 서버 없이 배포하려던
> 것인데, **프롬프트 한 줄을 고칠 때마다 두 군데를 똑같이 손봐야 했다.** 하루에만 문체 지시·
> 파서 수정·명찰 지시를 세 번 두 번씩 넣었다. 지웠다.

### 0.1 왜 두 번 부르나 — 결재 게이트 때문이다

서버리스 함수는 **사람을 기다리는 동안에도 실행 시간을 태운다.** ②배정 뒤에 결재를 받는
우리 파이프라인은 한 번에 돌릴 수 없다 (Hobby 상한 60초).

```
POST /api/plan   ① 기획 + ② 배정까지 (LLM 2회) → 목차를 돌려주고 함수가 끝난다
     ── 사람이 승인/반려를 누른다. 이 동안 함수는 돌지 않는다 ──
POST /api/run    승인된 목차를 받아 ③ 조사부터 SSE 로 흘린다
```

**`run_from()` 은 배정을 다시 돌리지 않는다.** 사람이 승인한 시작 문서가 2단계에서 바뀌면
결재가 헛것이 된다. `plan["승인됨"]` 이 그 표시다.

반려하면 사유를 실어 `/api/plan` 을 다시 부른다 — 편집장이 그 사유를 반영해 목차를 다시 짠다.
브라우저가 `approval.result` 를 만들어 큐에 넣는다.

**의미 이벤트 13종이 유일한 계약이다.** 그림·대사·배치를 아무리 바꿔도 녹화 22편을
다시 뜰 필요가 없는 이유가 이것뿐이다. 스키마를 바꾸는 건 별도 확인 사항이다.

## 1. 등장인물 7명

10명에서 7명으로 줄였다. 구조가 **코디네이터 1명 + 서브에이전트 N명** 이기 때문이다.
①기획 ②배정 ④점검 ⑤종합은 전부 코디네이터가 한다. 따로 사람을 세우면 화면이 구조를 잘못 말하게 된다.

| 이름 | 하는 일 | 자리 | 색 | LLM |
|---|---|---|---|---|
| **편집장** | ①기획 ②배정 ④점검 ⑤종합 (코디네이터) | `editor` | `#e8f0f7` 화이트 | ⭕ (④는 0회) |
| 김기자 | ③조사 | 책상 1 | `#ff6b6b` 빨강 | ⭕ |
| 이기자 | ③조사 | 책상 2 | `#ffd166` 노랑 | ⭕ |
| 박기자 | ③조사 | 책상 3 | `#51cf66` 초록 | ⭕ |
| 최기자 | ③조사 | 책상 4 | `#4dabf7` 파랑 | ⭕ |
| 정기자 | ③조사 | 책상 5 | `#c77dff` 보라 | ⭕ |
| **최계량** | ⑥평가 (사람이 아니라 재는 노드) | `score` | `#ff922b` 주황 | ❌ |

기자 색은 **기능색**이다. 서고 블레이드가 이 색으로 점등해 "누가 읽었나"를 보여주고,
한 블레이드가 두 색으로 갈리면 그게 중복 읽기다. 그래서 상태색(앰버·레드·그린)과
겹치지 않게 밝은 쪽으로 갈라 놓았다 (`config.js` `BADGE_COLORS`).

### 1.1 명찰 10장 — 남겨 둘지 미정

편집장이 축 하나를 고르고 명찰 5장을 나눠 준다.

| 축 | 화면 이름 | 명찰 5장 | 나누는 기준 |
|---|---|---|---|
| `서사` | **사건** | 큰그림 · 시간순 · 인물 · 원인 · 비교 | 파고드는 **방법** — 대상이 무엇이든 쓸 수 있다 |
| `측면` | **작품** | 스토리 · 제작 · 흥행 · 캐스팅 · 세계관 | 영화라는 대상의 **구성 요소** — 위키 절 이름(Plot·Production·Reception·Cast·Phase) 그대로 |

**내부 키(`서사`·`측면`)는 건드리지 않는다.** 녹화 22편에 그대로 저장돼 있고 프롬프트도 그 글자로
축을 고른다. `config.js` 의 `AXIS` 가 **화면에 띄울 이름과 설명만** 따로 들고 있다
(`shortRole` 이 '담당'을 떼는 것과 같은 방식). 배지에 마우스를 올리면 설명이 뜬다.

> 「측면」은 **무엇의 측면인지**를 말해 주지 않아 와닿지 않았다. 실제로는 *작품에 관한 것들*이다.

**축은 명찰만 바꾸는 게 아니다.** ② 배정에서 문서 고르는 규칙이 뒤집힌다.

```js
const 주변안내 = 축 === '측면'
  ? "이 보고서는 제작·흥행 쪽을 다루므로 '— Production' '— Reception' 조각이 오히려 알맹이다."
  : "'— Music' '— Reception' '— Marketing' '— Release' 로 끝나는 조각은 줄거리가 없으니 피하라.";
```

코퍼스 51건이 그렇게 쪼개져 있기 때문이다 — 통문서 16 · `— Overview` 13 · `— Production` 7 ·
`— Reception` 5 · `— Music` 4 · 나머지 6. **같은 문서가 축에 따라 알맹이도 되고 쓰레기도 된다.**

### ⚠ 작품 축에서는 명찰이 무너진다 (실측)

녹화 22편에서 절 5개에 붙은 **서로 다른 명찰의 수**를 셌다.

| 축 | 편수 | 서로 다른 명찰 (평균) |
|---|---|---|
| 사건(`서사`) | 13편 | **4.1 / 5** |
| 작품(`측면`) | 9편 | **2.2 / 5** |

`q5`(「페이즈 1~3이 어떻게 이어지는가」)는 **역할을 켰는데도 4편 전부** 다섯 명이 `세계관` 하나였다.
원인은 둘이다.

1. **코드에 겹침 방지가 없다.** 시작 문서는 `taken` 집합으로 중복을 막는데 명찰은 목록에 있는지만 본다.
   프롬프트도 *"고른 축의 명찰에서 골라라"* 라고만 하고 **"서로 다르게"** 라고 하지 않는다
2. **질문이 한 면만 묻는다.** 「페이즈가 어떻게 이어지는가」는 작품 축 다섯 중 세계관(Phase)에만 해당한다.
   사건 축은 어떤 질문에도 다섯 방향이 나오지만, 작품 축은 질문이 그 면을 안 물으면 빈다

다섯이 같은 명찰을 받으면 **프롬프트가 다섯 개 다 똑같다** — 그 실행에서 역할은 아무 일도 하지 않는다.
역할이 이름표에 불과하다는 말이 여기서는 **이름표조차 하나**인 셈이다.
**조치 (2026-09-27)** — 코드로 강제하지 않고 **기획 프롬프트로 권한다** (두 파이프라인 같이).
없는 다양성을 코드가 지어내면 측정이 흐려지기 때문이다.

```
Prefer DIFFERENT badges for different sections. Repeat a badge only when the question
genuinely has no other facet to split on — never force a badge that does not fit the section.
```

⚠ 녹화 22편은 그대로라 **효과는 새 녹화·라이브에서만** 보인다.

> ⚠ **절제 실험에서 역할은 값을 증명하지 못했다** (1회씩 잰 표에서 5개 질문 전부 역할 끈 쪽
> 근거율이 높았다). 다만 칸당 3회로 다시 재니 차이가 잡음보다 작아 **판단 보류**로 남겼다.
> 명찰 기능은 지우지 않고 기본값도 켠 채 둔다 — 아래 9장.

## 2. 무대

### 2.1 좌표계 — 진짜 아이소메트릭 30°

```js
TILE = { W: 64, H: 64 / Math.sqrt(3) }        // ≈ 64 × 36.95
x = ox + (gx - gy) * TILE.W / 2 * s
y = oy + (gx + gy) * TILE.H / 2 * s
기울기 = atan(TILE.H / TILE.W) = 30.000°
```

비율은 `config.js` 의 `TILE` **한 줄에만** 있다. 2:1 다이메트릭(26.565°)에서 옮겨 왔다 —
기성 2D 팩에 맞추려던 이유였는데 에셋을 직접 만들기로 하며 사라졌다.

화면 방향을 헷갈리지 않게 한 번 적어 둔다.

- `+gx` → 화면 **오른쪽 아래**
- `+gy` → 화면 **왼쪽 아래**
- `gx + gy` 가 클수록 카메라에 가깝다 → **이 값 하나로 사람·집기 그리는 순서를 정한다**
- 상자가 보여주는 세로 면은 둘뿐이다 (`+gx` 면 · `+gy` 면) + 윗면 마름모
- 캐릭터만 예외로 빌보드(카메라 정면)로 둔다

### 2.2 방 — 바닥 한 장, 벽 두 면

```js
ROOM = { gx0: -0.55, gx1: 11.5, gy0: 0, gy1: 10.2, h: 132 }
```

- **바닥** — 격자 마름모를 그대로 쓰되 `ctx.clip()` 으로 **방 사각형 안쪽만** 그린다.
  무한 평면으로 깔면 사무실이 아니라 허허벌판이 된다.
- **벽 2면** — `gy = gy0`(서고가 등을 대는 오른쪽 뒷벽) · `gx = gx0`(왼쪽 뒷벽, 한 톤 어둡게).
  둘이 방 꼭대기에서 모서리로 만난다. 그라데이션 + 세로 이음매 + 굽도리 + 윗테두리.
- **카메라** — `resize()` 가 방 네 귀퉁이를 `sx = gx-gy` / `sy = gx+gy` 로 옮겨 통째로 담는다.
  사람·집기가 벽 밖으로 조금 넘치므로 여유 1칸.

### 2.3 서고 7개 — 벽에 붙어 한 줄

```js
racks: [...Array(7)].map((_, i) => at(0.75 + i * 1.55, 0.33))
RACK = { gw: 1.35, gd: .62, minH: 84, perDoc: 8.2, base: 42 }
```

- **gy 0.33 = 깊이(0.62)의 절반** → 뒷면이 벽(gy 0)에 닿는다
- **앞면은 `+gy`**(화면 왼쪽 아래). gx 쪽으로 넓고 gy 쪽으로 얇아야 한 줄로 서도 옆을 안 가린다
- 높이 = `42 + 건수 × 8.2` (최소 84) → **건수가 높이로 읽힌다**
- **건수 내림차순으로 세운다** (`world.js` `loadRacks`). 높은 랙이 뒤(왼쪽)로 가야 앞을 안 가리고,
  이름표 줄 간격도 27.8px 이상으로 일정해진다

```
우주·마법 11 → 뉴 제너레이션 11 → 세계관 허브 9 → 어벤져스 7
→ 캡틴 아메리카 5 → 토르·헐크 5 → 아이언맨 3          (문서 51건)
```

- **블레이드 1칸 = 문서 1건.** 상태 넷이 구분된다.

| 상태 | 그림 |
|---|---|
| 안 읽음 | 흐린 시안 토막 |
| 읽음 | 읽은 기자 색 **꽉 찬 막대** + 은은한 번짐 |
| **헛읽음** | 같은 색인데 **끊어진 막대**(네 토막, 42% 농도) — 갔다 왔는데 이 절과 상관없던 문서 |
| 중복 | 색이 갈리고 위에 흰 띠 |

> **불은 도착해야 들어온다.** 예전에는 이벤트가 오는 즉시 점등해서, 기자가 아직 1초를
> 걸어가는 동안 블레이드가 먼저 켜졌다 — 읽는 장면보다 결과가 앞섰다.
> 이제 `moveTo` 의 도착 콜백에서 점등·헛읽음 집계를 함께 한다 (한 번만 세도록 잠금).
> 실측: 13건 전부 점등 순간 기자↔서가 거리 **1.84칸** = 앞자리(`rack.at + 1.3,1.3`).
>
> 헛읽음은 원래 **구분되지 않았다.** 회색으로 칠하는 가지가 있었지만 `readers.length === 0`
> 일 때만 닿는데, `relevant` 는 `research.read` 에서만 정해지고 그 자리에서 `readers` 도
> 채워진다 — 도달할 수 없는 죽은 코드였다. 실측으로 잡았다 (헛읽은 3건 전부 `readers = 1`).
- **이름표** — 배경판 없이 한 줄 「`아이언맨 (3건)`」. 그 랙 윗면 바로 위(`Nt[1] - 7*s`).
  어두운 벽 위라 글자 뒤에 짙은 외곽선을 깐다

> 이름표가 겹쳤던 적이 있다. 원인은 **랙 높이가 건수에 비례해서**였다 — 어벤져스(7건, 99px)와
> 우주·마법(11건, 132px)은 랙이 33px 더 높아, 오른쪽으로 갈수록 28px씩 내려가는 걸 상쇄해
> 같은 줄에 올라탔다. 건수 내림차순 정렬이 이걸 같이 해결한다.

### 2.4 집기 8개

사람보다 **반 칸 앞**(`+0.55`)에 둔다. 그래야 사람이 집기 뒤에 선 모습이 되고 다리가 살짝 가려져
바닥에 붙어 보인다. 사람과 **같은 `gx+gy` 정렬 배열**에 넣어 한 번에 그린다.

| 집기 | `kind` | 자리 | 하는 일 |
|---|---|---|---|
| 기자 책상 ×5 | `console` | `desks[i] + 0.55` | 상판에 서류 한 장 |
| 편집장 책상 | `console` | `editor + 0.55` | 〃 |
| **회의 탁자** | `table` | `MEET.table` | 절 원고 5장 + **④ 점검 램프** 🟠빈 절 / 🟢통과 |
| **최계량 책상** | `outbox` | `score + 0.55` | **심사대 + 발행함 겸용.** 결재함 두 칸이 어긋나게 겹쳐 있고, 완료되면 위 칸이 원고 색으로 바뀌며 🔴**발행** |

> 삭제한 것 — 나배정 디스패치 콘솔 · 정반송 심사대 · 윤카피 교열 부스(사람이 없어짐),
> 별도 점검 램프 부스(반송은 회의 탁자에서 일어난다), 최계량 부스(책상에 합침),
> 그리고 책상 위 **홀로그램 모니터**(홀로그램으로도 안 보이고 이 이야기와 상관도 없었다).

### 2.5 회의 탁자

```js
MEET = { table: at(5.4, 8.0), editor: at(3.0, 8.0),
         reps: [ at(4.3,6.7), at(5.8,6.7), at(7.3,6.7), at(5.0,9.3), at(6.5,9.3) ] }
```

먼 줄 3 · 가까운 줄 2 로 엇갈린다. 같은 줄에 붙이면 이름표가 서로 가린다.
**모이지 않고 자리에서 말하면 회의로 보이지 않는다** — 이동이 곧 "지금 회의 중"이라는 신호다.

| | 인칭 | 자리 | 하는 일 |
|---|---|---|---|
| **자막** | 3인칭 해설 | 무대 위 띠 (DOM) | 무슨 일이 벌어졌나 |
| **대사** | 1인칭 | 머리 위 말풍선 (캔버스) | 누가 무슨 말을 하나 |

문장은 **`script.js` 한 파일에서만** 만든다. 파이프라인은 이 문장들을 모른다.

| 규칙 | 값 | 왜 |
|---|---|---|
| 한 번에 한 명만 말한다 | — | 각자 큐를 돌리면 다섯이 동시에 떠들어 회의로 안 보인다 |
| 합창 | `'all'` | 「네. 알겠습니다」는 절을 받은 기자 전원이 같이 |
| 타자 속도 | `CPS = 26` 자/초 | 다 친 뒤 `HOLD = 0.8` 초 머문다 |
| 대사 중 재생 정지 | `queue.hold = () => 말하는중(world)` | 짧으면 회의로 안 보인다 |
| 배속은 말·걸음에 똑같이 | `dt × queue.speed` | 대사만 빨라지면 걷는 중에 회의가 끝난다 |
| 모이기 | 1.9s(승인) · 1.6s(보고) | |
| 흩어지기 | 1.4s(파견) · 1.6s(마무리) | `afterTalk` — 말이 끝나야 움직인다 |
| 쪽지 | 0.42s 간격, 각 0.9s | 한꺼번에 뿌리면 뭉쳐 보인다 |

### 3.1 시작 문서는 말하지 않고 **쪽지로 건넨다**

**기자들은 서로를 볼 수 없다.** 다만 A를 보낼 때 「B·C·D는 이 문서들을 맡았으니
너는 그쪽 말고」 라고 일러 줄 수는 있다.

개별 배정은 각자에게만 가는 것이고, 공통 규칙(「남이 보는 문서는 피하세요」)만 회의에서 말한다.
그래서 편집장이 「나눠준 문서를 먼저 확인하세요」를 말하는 순간 쪽지 5장이 차례로 날아간다.

### 4.1 한 번 나가면 다 읽고 돌아온다

`server/pipeline.py` 의 `조사()` 는 **for 루프 안에서 예산만큼 연달아 읽고**, 그 사이에 코디네이터와
주고받는 것이 없다. 다음 문서도 방금 읽은 문서의 링크(`frontier`)에서 고른다 —
즉 **서가 사이를 옆으로 옮겨 다니는** 동작이다.

> 예전에는 문서 한 건마다 자리로 돌아왔다. **있지도 않은 왕복을 3번** 한 셈이고,
> 둘러보다 남의 구역과 겹치는 장면(겹쳐 읽음 14.8%가 생기는 바로 그 지점)이 가려졌다.
>
> 실측 — 고친 뒤 `q1-기본` 에서 기자의 이동 순서:
> `자리 → 서가(5.2,1.6) → 서가(6.7,1.6) → 자리` · **자리 귀환 3회 → 1회**
> (같은 서가에서 두 건을 읽으면 움직이지 않는다)

격리는 **귀환 한 번**으로 보여 준다 — `pose='carry'`, 원문이 아니라 메모만 들고 온다.

**이동은 한 사람에 한 번에 하나다.** 조사 귀환(1.1s)이 끝나기 전에 보고 회의 소집이 들어오면
두 이동이 같은 사람을 동시에 끌어당겨 좌표가 튄다. `moveTo` 가 그 사람의 이전 이동을 버린다.

### 4.2 병렬성이 이 화면의 주인공

`dispatch` 이후 `review.done` 까지 기자 5명은 **동시에** 움직인다.
*"로그가 30초쯤 멈춰 있어도 정상 — 기자 다섯이 동시에 읽고 있는 중"* 이라는 상황이
이 화면에서는 **가장 바쁜 30초**로 보인다. 그게 이 시각화의 목적이다.

## 5. UI

### 5.1 상단 바 — 한 줄뿐이다

```
마블 리서치 데스크  [▶라이브][⏵재생][⚙설정]  "질문…"  [서사 축]  42.0초   재생·q1-기본  ❚❚ 1× 2× 4×
```

**세 갈래 탭은 상단 바에 늘 있다.** 모달 안에 두면 지금 어느 갈래인지 볼 수 없고,
바꾸려고 매번 창을 열어야 했다. 누르면 **바로 아래로 칸이 떨어진다** — 화면을 어둡게 덮지 않아
무대가 계속 보인다. 같은 탭을 다시 누르거나 바깥을 누르거나 Esc 로 닫는다.

| 표시 | 뜻 |
|---|---|
| 흐린 채움 (`.on`) | **지금 돌고 있는 갈래** — 재생 중이면 ⏵ 재생 |
| 시안 채움 (`.open`) | **지금 펼쳐 놓은 칸** |

**가로 공정 바는 없앴다.** 공정 칩마다 담당자가 적혀 있고 편집국 줄의 상태도 결국 같은
`world.nodes` 에서 나와서, **같은 것을 두 번 말하고 있었다.** 왼쪽 바에 합쳤다 (5.2).
`1280 × 62px` 를 돌려받아 무대 세로가 `770 → 832px` 로 늘었다.

「📄 보고서」 버튼도 뺐다 — 오른쪽 산출물 칸에서 여는 것과 같은 일이었다.

**시계는 기록의 시각이다.** 이벤트가 나올 때마다 `world.t = e.t` 로 맞춘다.
예전에는 "내가 본 시간"(벽시계)이라 58.7초짜리 실행에 129.9초가 찍혔다.
이제 끝의 「완료 58.7초」와 같은 축이다.

**일시정지는 한 곳에서 건다.** `const 흐름 = queue.paused ? 0 : dt` 를 만들어
`world.t` · `stepTalk` · `queue.step` · `renderer.draw` 에 같은 값을 넘긴다.
예전에는 `queue.step` 만 멈춰서 이벤트는 서는데 **걸음·말풍선·시계·팬은 계속 돌았다** —
버튼은 ▶ 로 바뀌는데 화면은 안 멈춘 것처럼 보였다.

### 5.3 편집국 · 공정 — 세로축이 ①→⑥ 이다

```
편집국 · 공정                        7명
① 기획   ● 편집장                  ✓ 완료
② 배정   ● 편집장                  ✓ 완료
🔏 결재   당신                      ✓ 완료
③ 조사   기자 5명                 ● 진행중
   │ ● 김기자   큰그림 · 인피니티…    💻 출발
   │ ● 이기자   시간순 · 각 스톤의…   💻 출발
   │ ● 박기자   인물 · 인물들의…      💻 출발
   │ ● 최기자   원인 · 사건의…        💻 출발
   │ ● 정기자   비교 · 인피니티…      💻 출발
④ 점검   ● 편집장   ↺ 재위임 1/2    ⏸ 대기
⑤ 종합   ● 편집장                  ⏸ 대기
⑥ 평가   ● 최계량                  ⏸ 대기
```

기자 5명이 ③ 아래 들여쓰기로 묶이니 **"편집장 혼자 ①②④⑤를 하고 ③만 다섯으로 갈라진다"**
는 **코디네이터 1명 + 서브에이전트 N명** 구조가 한 화면에 그대로 보인다. 그게 이 배열을 고른 이유다.

| 규칙 | 값 |
|---|---|
| 단계 상태 | 대기(회색) · 진행중(시안) · 완료(초록). `world.nodes[key]` 하나로 정한다 |
| 번호 | 동그란 배경 위에 **맨 숫자**(1~6). `FLOW` 의 `①②③` 을 그대로 쓰면 원이 겹쳐 숫자가 안 보였다. 🔏 는 그대로 |
| 앰버 | **사람 차례(🔏 결재)에만** 쓴다. 「기자 5명」까지 앰버면 어디가 사람 차례인지 안 보인다 |
| 재위임 칩 | 평소 점선 회색, 두 바퀴째가 실제로 돌 때만 앰버 |
| 상태 칸 | 격자 마지막 칸에 고정 — 줄마다 세로로 맞는다 |
| `●` 동그라미 | 기자 색 = 서고 블레이드 색 |
| 기자 상태 | `1,044자 · 인용 11`. **헛읽음이 있으면 뒤에 `· 헛읽음 2`** 를 붙인다 — 끝난 뒤에도 남는다 |
| 명찰 / 절 | **명찰은 기자 색**, 절 이름은 흐리게. 직원 직함은 색 없이 흐리게 |
| 값 글자 | 이름표와 **같은 크기**로 두고 굵기·밝기로만 강조 (`.u b` `.drow .dv`) |

**두 가지 상태가 사실을 못 박는다.**

- **`🔏 결재 전`** — ① 기획이 목차·담당·명찰을 **한 번에** 정하므로
  결재 전에도 배정이 보인다. 확정처럼 보이면 안 되니 앰버로 「결재 전」이라 쓰고 명찰·절을 흐리게 둔다.
  ②배정이 더하는 것은 **시작 문서뿐**이다.
- **`✓ 1바퀴만`** — 재위임으로 ②에 되돌아가도 **결재는 다시 묻지 않는다.**
  `setNode` 가 뒤쪽 노드를 전부 idle 로 되돌리는 바람에 결재 줄이 '대기'로 보였던 것을 고쳤다.

### 5.4 대시보드 — 평문 지표 7개

이름은 전부 평문이다. `근거율`·`격리율` 은 우리끼리 쓰는 말이라 처음 보는 사람에게는 안 읽힌다.
묶음 순서 = 읽는 사람이 궁금해하는 순서.

| 묶음 | 지표 | 단위 | 경고 | 그물 |
|---|---|---|---|---|
| **근거** 문장에 출처가 붙어 있나 | 근거가 달린 문장 | % | < 50 | |
| | 근거 없는 절 | 개 | > 0 | ✅ |
| **인용** 적어 둔 출처가 진짜인가 | 지어낸 인용 | 곳 | > 0 | ✅ 🔴 |
| | 바로잡은 인용 | 회 | — | |
| **분담** 다섯이 서로 다른 곳을 읽었나 | 한 문서에 쏠림 | % | ≥ 50 | |
| | 겹쳐 읽음 | % | ≥ 40 | |
| **격리** 원문이 위로 새지 않았나 | 편집장이 본 글 | % | > 30 | |

**그물** = `hard` 항목이 하나라도 걸리면 「확인 필요」.
통과는 *"읽어 볼 만하다"* 는 뜻일 뿐 *"좋은 보고서"* 라는 뜻이 아니다. 순위는 사람이 읽고 매긴다.

### 5.5 결재 모달 — 한 화면에 다 들어간다

```
🔏 목차 결재 — 최고 승인자(당신)의 확인이 필요합니다
│ 질문  인피니티 스톤을 둘러싼 주요 사건들은 무엇이고 각각의 원인은 무엇인가?
──────────────────────────────────────────────────
인피니티 스톤을 둘러싼 주요 사건과 원인      (서사 축)
5절 · 시작 문서 5개 모두 다름
  1  인피니티 스톤의 기원과 첫 등장  ● 김기자 / 큰그림 / 인피니티 스톤 먼저
     인피니티 스톤이 처음 등장한 사건과 그 배경을 설명한다.
  2  각 스톤의 주요 사건과 연관성   ● 이기자 / 시간순 / MCU 페이즈 1 먼저
  …
──────────────────────────────────────────────────
보고서 목차가 질문의 주제와 맞는지 확인해주세요        [반려] [승인]
```

**스크롤이 생기면 아래를 안 보고 누른다.** 그래서 어떤 창 높이에서도 한 화면에 들어가야 한다.
낮은 창에서는 `@media (max-height: 800px)` 가 **여백만** 줄이고 `max-height` 를 90vh 로 올린다 —
내용을 지우거나 접지 않는다. 질문은 한 줄로 줄이고 넘치면 말줄임한다.

| 창 높이 | 시트 내용 | 허용 | 스크롤 |
|---|---|---|---|
| 900 | 516px | 756px (84vh) | 없음 |
| 560 | **428px** | 504px (90vh) | 없음 |
| 480 | **429px** | 432px (90vh) | 없음 |

| 자리 | 규칙 |
|---|---|
| 질문 ↔ 보고서 | 제목 위 구분선으로 가른다 |
| 목차 한 줄 | `N · 절 제목 · ● 기자 / 명찰 / 시작문서 먼저` + 다음 줄에 설명 |
| 번호·기자·명찰 | 그 기자 색. 이름 앞 `●` 는 `.mhead u::before` 로 색을 물려받는다 |
| 코드가 보는 것 | 제목 아래 작은 한 줄 `5절 · 시작 문서 5개 모두 다름` (겹치면 앰버) |
| 사람이 봐야 하는 것 | 아래 문구 「보고서 목차가 질문의 주제와 맞는지 확인해주세요」 — **코드가 못 보는 것** |
| 반려 | 두 걸음. 「반려」를 누르면 그 자리에 사유 칸이 열리고 버튼이 「반려 확정」이 된다 (Enter 로도) |

> ⚠ **이 결재 단계는 우리가 더한 것이다.** 원래 구조는 사람이 눈으로 보고 그냥 넘어가고,
> 멈춤도 반려도 되돌아가는 길도 없다.
> A(그냥 직진) / B(확인만 하고 직진) / C(승인·반려 2갈래) 중 **C 유지**로 정했다 (2026-09-27).
> 화면에 안내 문구를 붙였다가 뺐다 — 결재 내용을 읽는 데 방해가 됐다. 기록은 여기 문서에만 둔다.

> 결재 대상은 **목차 + 배정 둘 다**다. 사람이 확인해야 할 세 가지 중 둘이 배정에 관한 것이고,
> **코드 검증은 형식만 본다** — 그게 질문에 맞는 문서인지는 확인하지 못한다.
> 그래서 「결재를 올리겠습니다」가 ②배정까지 끝난 뒤에 나온다.

### 5.6 보고서 — 무엇을 넣고 무엇을 뺐나

절 머리글에는 **제목만** 둔다. 누가 썼는지(명찰·기자)는 왼쪽 편집국이 보여 주므로 빼는 게 맞고,
녹화 22편에는 배역을 7명으로 줄이기 전 콜사인(알파·브라보·찰리·델타·에코)이 굳어 있기도 했다.

**본문과 출처를 가른다.** 기자는 문장 끝에 `«문서 제목»` 을 달아 근거를 남기는데,
제목이 문장 사이에 박혀 있으면 읽기가 어렵다. 그래서 ⑤ 종합이 조판할 때
**본문에는 번호만 두고 제목은 맨 끝 「참고자료」로 모은다.**

```
본문   … 여섯 개의 가상의 아이템입니다.[1] 각 스톤은 특정한 힘을 지닙니다.[1]
참고   1. Infinity Stones   2. Avengers: Age of Ultron — Overview   …
```

**글자수는 참고자료를 뺀 본문만 센다** (`synthesize.done.chars` · `metrics.보고서자수` ·
산출물 칸 · 마무리 대사 전부 같은 기준). 실측 `q1-기본` 5,044자 → **4,133자** · 참고자료 8건.

> ⚠ **절 본문(state 의 `정렬[].본문`)은 건드리지 않는다.** ⑥ 평가의 「근거가 달린 문장」은
> 그걸 세므로 이 조판은 지표에 영향을 주지 않는다. 조판은 **보고서를 엮을 때만** 일어난다.

규칙은 [`web/js/report.js`](../web/js/report.js) 와 `server/pipeline.py` 의 `조판()` 두 곳에
같은 내용으로 있다 (절대 규칙 5). **멱등이다** — 이미 갈라진 보고서를 다시 넣어도 그대로다.
그래서 화면은 옛 녹화(«» 가 본문에 박힌 것)와 새 기록을 같은 코드로 그린다.

> **파서 흔적 버그** — 절 끝에 `","충분":true,"부족":""}` 가 찍혀 있었다.
> 기자가 절을 쓸 때 `{"본문":"…","충분":true,"부족":""}` 로 받는데, JSON 파싱이 깨지면
> **앞머리만 떼고 꼬리를 안 뗐다.** `본문만()` 을 만들어 앞뒤를 둘 다 떼고 이스케이프도 되돌린다
> (두 파이프라인 같이). 이미 찍힌 22편은 **고치지 않고** 볼 때만 걷어낸다 — 실제 실행 기록이다.

**문체** — ①안(그대로 이어 붙이고 머리말·맺음말만)을 고르면 **문체가 들쭉날쭉해진다**
를 대가로 받아들였다. ②안(편집장이 다시 쓴다)은 문체를 통일하는 대신 **격리가 무너지고 인용이 샌다.**

우리는 **쓰는 자리에서** 맞추기로 했다 (2026-09-27). ③ 조사 프롬프트와 ⑤ 머리말·맺음말 프롬프트에
`모든 문장은 '~습니다/~입니다' 체로 끝낸다` 한 줄을 넣는다. 편집장은 여전히 원문을 안 보므로
격리도 인용도 그대로다. **다만 녹화 22편은 그대로라 효과는 라이브 실행과 새 녹화에서만 보인다.**

### 5.7 패널 — 라이브 · 재생 · 설정

상단 바의 탭을 누르면 그 아래로 칸이 떨어진다. 한 번에 한 갈래만 보인다 —
예전에는 네 덩이(기록 목록·실행 설정·키·직접 실행)가 한 장에 쌓여 있어 무엇부터 봐야 할지
알 수 없었다.

| 탭 | 내용 |
|---|---|
| **▶ 라이브** | 질문을 직접 넣고 한 번 돌린다. 절제 토글 4개(역할·배정·구역·재위임) · 예상 $0.025. 키가 없으면 「⚙ 설정에서 키를 넣어 주세요」 안내가 뜨고 그 글자를 누르면 설정 탭으로 간다 |
| **⏵ 재생** | **질문 × 설정 두 축**으로 고른다 (아래) |
| **⚙ 설정** | API 키 입력·저장·삭제. 키는 **이 브라우저(localStorage)에만** 저장된다 — 애초에 서버가 없다 |

**재생을 두 축으로 나눈 이유** — 22편을 한 줄로 늘어놓으면 **무엇이 무엇의 대조군인지** 안 보인다.
녹화는 `질문 5개 × 설정 4가지` 격자이고, 짝은 *"같은 질문을 설정만 바꿔 돌린 것"* 이다.

```
① 질문   [서사] 인피니티 스톤을 둘러싼 …      ← 축 배지 + 제목 한 줄
         [측면] MCU 영화들은 어떻게 제작되었고 …
         …5개

② 설정   전부 켜고(기준)        시작 문서를 안 나눠 줌(배정·구역 끔)
         기자 역할을 안 줌(역할 끔)  빈 절을 안 되돌림(재위임 끔)

→ q4-역할끔   근거가 달린 문장 54.5% · 지어낸 인용 0곳 …     [이 기록 재생]
   실행 설정  절수 5 · 절예산 3 · 최대바퀴 2 · 역할 꺼짐 · 배정 켜짐 …
```

- 설정 이름은 **평문**으로 둔다 — `구역끔` 은 우리끼리 쓰는 말이다
- 축 배지는 색으로 가른다 — **서사 청록 `#5ec8e0` · 측면 보랏빛 `#b9a0e8`**.
  분류이지 상태가 아니라 둘 다 차가운 쪽에서 골랐고 상태색(앰버·레드·그린)은 피했다.
  결재 모달의 축 배지도 같은 색을 쓴다
- 그 조합으로 돌린 기록이 없으면 버튼을 흐리게 하고 누를 수 없게 한다
- **반려 분기(`q1-반려`)는 메뉴에 두지 않는다** — `q1-기본` 재생 중 [반려] 를 누르면 그때 이어 붙는다

**같은 설정 다시 돌림** — 한 조합에 기록이 둘 이상이면 나머지를 **그 질문 아래에만** 따로 보여 준다.
`q2` 가 그렇다. 질문·설정(`절수 5 · 절예산 3 · 역할·배정·구역·재위임 전부 켜짐`)이 글자 하나까지
같은데 결과가 다르다.

| | 근거가 달린 문장 | 한 문서에 쏠림 | 겹쳐 읽음 | 근거 없는 절 |
|---|---|---|---|---|
| `q2-기본` | 23.7% | 35.7% | 8.3% | 2개 |
| `q2-측면` | 29.3% | 29.4% | 0.0% | 1개 |

**설정이 아니라 흔들림을 보여 주는 기록**이라 두 축에는 들어가지 않는다.
예전에는 이걸 「그 밖의 기록」으로 맨 아래에 늘 띄워, q2 와 상관없는 질문을 골라도 보였다.

한 화면에 들어가야 해서 질문은 한 줄, 실행 설정은 칩 한 줄로 뒀다 (892 → **693px** / 허용 756px).

**보고서는 끝나면 저절로 열린다.** 맨 위에 「● 보고서가 발행되었습니다」 한 줄이 붙고 바로 본문이다.
닫은 뒤에는 **산출물 → 📄 보고서**(`5,044자 · 열기`)로 다시 연다.

> 예전에는 화면 아래에 완료 배너가 떠서 `5,044자 · 근거가 달린 문장 61.8% · 지어낸 인용 0곳 ·
> 58.7초 · 모델 호출 30회` 를 알려 줬다. **그 다섯 개가 전부 다른 곳에 이미 있었다** —
> 자수는 산출물, 근거율·지어낸 인용은 대시보드, 경과는 상단 시계, 호출 수는 사용량.
> 같은 숫자를 여섯 번째로 적는 대신 **결과물 자체를 편다.**
>
> 여는 시점은 `finished && !world.talk && !world.convo.length` — 마무리 대사가 끝난 뒤다.
> 바로 열면 편집장이 *"이대로 올리겠습니다"* 하는 장면을 가린다. 실측 1.1초 뒤에 열린다.
