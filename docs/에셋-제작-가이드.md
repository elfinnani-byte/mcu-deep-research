# 🎨 에셋 제작 가이드 — ChatGPT(GPT-Image)로 관제실 그리기

> 2026-09-23 · 대상: `web/js/sprites.js` 가 그리는 집기 4종 + 캐릭터 10명
> 수치는 전부 코드에서 직접 뽑았다. 손으로 옮겨 적은 값이 아니다.

**한 줄 요약** — 투영을 **30° 진짜 아이소메트릭**으로 옮겼고, GPT-Image 가 **투명 PNG 를 바로 준다.**
그래서 예전 계획의 걸림돌 둘(각도 우기기·배경 빼내기)이 사라졌다.
이제 남은 어려움은 **10장을 같은 그림체로 뽑는 일** 하나다.

> ⚠ 아래 프롬프트는 **아직 돌려보지 않았다.** 첫 판을 뽑아 고쳐 가며 쓰는 출발점이다.
> API 파라미터 이름은 최신 문서와 대조하고 쓰는 게 안전하다.

---

## 0. 무엇이 바뀌었나

| | 전 | 후 |
|---|---|---|
| 투영 | 2:1 dimetric (26.565°) | **진짜 아이소메트릭 30°** |
| 이유 | 기성 2D 팩이 전부 2:1 | 에셋을 직접 만들기로 해서 그 이유가 사라짐 |
| 배경 | 마젠타로 받아 후처리로 키잉 | **투명 PNG 직접 수령** |
| 도구 | 나노 바나나 | **ChatGPT · GPT-Image** |

투영 변경은 `config.js` **한 줄**이었다. 비율이 거기에만 있고 나머지는 전부 파생되기 때문이다.

```js
export const TILE = { W: 64, H: 64 / Math.sqrt(3) };   // ≈ 64 × 36.95, 정확히 30°
```

## 1. 절대 규격 — 여기서 어긋나면 화면에서 따로 논다

### 1.1 투영

**진짜 아이소메트릭(true isometric) 30°.** 세 축이 화면에서 120°씩 벌어지고,
세 방향 모두 같은 비율로 줄어드는 그 투영이다.

```
타일  64 × 36.95 px      가로:세로 = 2 : 2/√3
기울기 = atan(36.95 / 64) = 30.000°
```

이건 이미지 모델이 **"isometric" 하면 기본으로 내놓는 각도**다. 3D 도구에서 카메라를
`(1, 1, 1)` 에 두고 직교 투영해도 그대로 30°가 나온다. 우길 일이 없다.

프롬프트에 넣을 말:
> *True isometric projection, 30 degrees, orthographic. No perspective, no vanishing point.*

### 1.2 크기 (화면 배율 s=1 기준)

| 집기 | 바닥 칸 (gw × gd) | 바닥 마름모 | 몸통 높이 | 전체 크기 | 앵커 보정 |
|---|---|---|---|---|---|
| 기자 콘솔 `console` | 0.92 × 0.78 | 54.4 × 31.4 | 12 | **54 × 43** | 15.7 |
| 기획 테이블 `table` | 1.70 × 1.30 | 96.0 × 55.4 | 12 | **96 × 67** | 27.7 |
| 부스 `booth` | 0.95 × 0.95 | 60.8 × 35.1 | 12 | **61 × 47** | 17.6 |
| 발행함 `outbox` | 1.05 × 1.05 | 67.2 × 38.8 | 10 | **67 × 49** | 19.4 |
| 서고 랙 `rack` | 0.58 × 2.05 | 84.2 × 48.6 | 84~132 | **84 × 133~181** | 24.3 |
| 캐릭터 | — | — | — | **32 × 48** | 0 (발이 기준점) |

화면 배율 `s` 는 창 크기에 따라 **0.5 ~ 1.25** 로 움직인다. 원본은 위 크기의 **3배**로 만들어
다운샘플한다 — 콘솔 **163 × 130**, 캐릭터 **96 × 144**.

> **서고 랙은 만들지 않는다.** 문서 건수(3~11)에 따라 키가 자라야 해서 고정 크기 그림으로는
> 표현이 안 된다. 어제 실제로 붙여 보고 확인한 결론이다
> ([에셋-라이선스-조사 4장](에셋-라이선스-조사.md)). 랙은 코드 드로잉으로 둔다.

### 1.3 색

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--bg` | `#0d1b2a` | 배경 |
| 바닥 | `#122236` / `#0f1e30` | 체크 무늬 두 톤 |
| 집기 윗면 | `#22344a` | 가장 밝은 면 |
| 집기 `+gx` 면 | `#18263a` | 앞면 (중간) |
| 집기 `+gy` 면 | `#101b28` | 옆면 (가장 어두움) |
| `--holo` | `#4cc9f0` | 테두리 · 홀로그램 |
| `--paper` | `#f4e9d8` | **원고만** |
| 기자 5색 | `#4cc9f0` `#ffd166` `#6ee7b7` `#c77dff` `#ff8fa3` | 몸통 |
| 직원 공통 | `#8aa4bd` | 몸통 |

**상태색은 사람·집기에 쓰지 않는다.** `--amber #ffb703`(경고) · `--red #e63946`(허위인용) ·
`--green #52b788`(통과)는 상태 전용이다.

**테마 한 줄** — *관제실은 전부 홀로그램인데 원고만 종이다.* 차가운 남색·시안 속에
베이지색 종이 한 장이 날아다니는 대비가 이 프로젝트의 핵심이다.

### 1.4 면 세 개의 밝기 규칙

아이소메트릭 상자는 **면이 딱 세 개만 보인다.**

```
        ╱▔▔▔╲        윗면      #22344a   가장 밝게
      ╱       ╲
     │   앞면  │      +gx 면   #18263a   중간 — 화면 오른쪽 아래를 본다
     │  (밝음) │
     ╲         ╱      +gy 면   #101b28   가장 어둡게 — 화면 왼쪽 아래
```

세 면의 밝기 차가 분명해야 입체로 읽힌다. 그라데이션 말고 **면마다 단색**이 좋다.

## 3. 두 가지 경로 — API 가 확실하다

### 3.1 API (권장)

투명 배경을 **파라미터로 지정**할 수 있어 결과가 일정하다.

```python
from openai import OpenAI
client = OpenAI()

r = client.images.generate(
    model="gpt-image-1",
    prompt=PROMPT,
    size="1024x1024",          # 또는 1536x1024(가로) · 1024x1536(세로)
    background="transparent",  # ★ 이 한 줄이 마젠타 키잉을 없앤다
    output_format="png",
    quality="high",
    n=1,
)
open("raw.png", "wb").write(base64.b64decode(r.data[0].b64_json))
```

**크기는 세 가지뿐이다** — `1024x1024` · `1536x1024` · `1024x1536`.
포즈 6개를 한 줄로 뽑을 때는 **가로형 `1536x1024`** 를 쓴다.

스타일을 맞출 때는 기준 이미지를 첨부하는 편집 엔드포인트를 쓴다.

```python
r = client.images.edit(
    model="gpt-image-1",
    image=[open("hero.png", "rb")],   # 기준 장
    prompt="Match this exact art style. " + PROMPT,
    size="1536x1024",
    background="transparent",
)
```

### 3.2 ChatGPT 화면

프롬프트에 *"transparent background, PNG"* 를 넣으면 대개 되지만 **보장은 안 된다.**
투명이 안 나오면 5장 끝의 **마젠타 대안**으로 돌아간다.

## 4. 공통 프롬프트 블록

아래를 **모든 요청 앞에** 그대로 붙인다.

```
Game asset sprite for a 2D isometric web game. Strict requirements:

PROJECTION: true isometric projection, 30 degrees, strictly orthographic.
No perspective, no vanishing point, no camera lens distortion.
The object is viewed from above at the standard isometric game camera angle.

BACKGROUND: fully transparent. No ground plane, no cast shadow, no reflection,
no backdrop, no vignette. The object must not touch the image border.

STYLE: clean flat vector shading, crisp hard edges, no texture noise,
no photorealism, no soft lighting, no ambient occlusion, no bloom.
Exactly three flat tones per object: top face lightest, the face pointing
lower-right mid, the face pointing lower-left darkest.
A thin 1px cyan rim light (#4cc9f0) along the silhouette edges.

PALETTE: dark navy sci-fi control room.
Body tones #22344a (top) / #18263a (lower-right face) / #101b28 (lower-left face).
Accent and rim light cyan #4cc9f0 only. Do not use orange, red or green.

NO TEXT. No letters, numbers, logos, labels, watermarks, UI or signage anywhere.

A single centered object. Nothing else in the frame.
```

**왜 "NO TEXT" 를 대문자로 쓰나** — GPT-Image 는 글자를 꽤 잘 그리는 대신 **부르지 않아도 넣는다.**
서가 이름·건수·이름표는 전부 코드가 그리므로 그림에는 글자가 없어야 한다.

**왜 "no soft lighting" 인가** — GPT-Image 는 기본값이 "예쁜 3D 렌더"라
그냥 두면 부드러운 그림자와 따뜻한 조명을 얹는다. 우리 화면과 안 맞는다.

```
The feet sit at the very bottom of the object, centred horizontally.
```

### 5.6 캐릭터 — 나머지 5포즈 (기준 장을 첨부)

`size="1536x1024"` · 편집 엔드포인트에 5.5 결과를 넣고:

```
Match the attached reference image exactly — same character, same proportions,
same palette, same line weight, same head size, same silhouette.

Produce ONE image containing the SAME character in five poses,
side by side in a single horizontal row, evenly spaced,
all standing on the same baseline, all the same height, all facing the viewer:

1. WALK   — mid stride, one leg forward, arms swinging in opposition
2. TYPE   — both arms forward and slightly down, hands at an invisible keyboard
3. CARRY  — both arms forward, holding a small beige #f4e9d8 sheet of paper
            flat in front of the chest
4. WAIT   — arms folded across the chest
5. REJECT — one arm raised up and out to the side, palm forward, like "stop"

Transparent background. No text, no numbers, no labels, no dividers between poses.
```

직원용은 5.5 를 그대로 쓰되 `POSE` 를 `wait`(팔짱)로 잡고 몸통을 조금 더 각지게 요청하면
기자와 구분된다.

### 5.7 투명이 안 나올 때 — 마젠타 대안

ChatGPT 화면에서 투명이 실패하면 배경 문단만 이렇게 바꾼다.

```
BACKGROUND: completely flat solid magenta #FF00FF, edge to edge.
No gradient, no vignette, no ground plane, no cast shadow.
```

우리 팔레트에 마젠타가 없어서 오검출 없이 빼낼 수 있다. 빼내는 코드는 6.1 에 있다.

## 6. 후처리

### 6.1 (대안 경로일 때만) 마젠타 빼내기

```python
from PIL import Image
import numpy as np

im  = Image.open("raw.png").convert("RGBA")
a   = np.array(im).astype(np.int16)
rgb = a[:, :, :3]

mag = (rgb[:,:,0] > 150) & (rgb[:,:,2] > 150) & (rgb[:,:,1] < 110)
a[:, :, 3][mag] = 0

# 경계에 남는 마젠타 테두리 — 초록을 빨강·파랑의 중간값으로 끌어올린다
edge = (~mag) & (rgb[:,:,0] > 120) & (rgb[:,:,2] > 120) & (rgb[:,:,1] < 90)
a[:, :, 1][edge] = ((a[:,:,0] + a[:,:,2]) // 2)[edge]

Image.fromarray(a.astype(np.uint8)).save("keyed.png")
```

API 로 `background="transparent"` 를 썼다면 이 단계는 건너뛴다.

### 6.2 잘라내고 크기 맞추기

투명하지 않은 픽셀의 경계 상자로 자른 뒤 **가로 폭**을 1.2 절 표의 3배에 맞춘다.
세로는 비율대로 따라오게 둔다 — **억지로 늘리면 30°가 깨진다.**

### 6.3 앵커 — 제일 자주 틀리는 곳

코드가 넘기는 `(x, y)` 는 **바닥 칸의 중심**이지 그림의 아래끝이 아니다.
아이소메트릭 바닥 마름모의 한가운데다.

```
앵커 y = 그림 아래끝 − (gw + gd) × TILE.H/4 × s
```

1.2 절 표의 **앵커 보정** 칸이 그 값이다 (s=1 기준).
**캐릭터는 다르다 — 발끝이 곧 `(x, y)`** 이므로 보정이 없다.

### 6.4 캐릭터는 회색조로

기자 5색 + 직원 슬레이트를 코드가 입힌다. 그림은 회색조 한 벌이면 된다.

```js
// 회색조 원본에 몸통색을 입힌다
octx.drawImage(img, 0, 0);
octx.globalCompositeOperation = 'source-atop';
octx.fillStyle = color;
octx.globalAlpha = .55;
octx.fillRect(0, 0, w, h);
```

## 7. 붙이는 법

`sprites.js` 는 처음부터 **교체를 전제로 만든 어댑터**다. 계약만 지키면 바깥은 안 건드린다.

```js
// sprites.js — 이미 있는 로더를 쓴다
useImage('console', 'assets/console.png');

export function drawProp(ctx, { x, y, kind, s, t, state }) {
  if (ready(kind)) {
    const img = image(kind), A = ART[kind];
    const w = A.w * s, h = w * img.height / img.width;
    ctx.drawImage(img, x - w/2, y - h + A.anchor * s, w, h);
    return;                       // ← 그림이 있으면 여기서 끝
  }
  ...기존 도형 코드...             // ← 없으면 지금 그대로 (화면이 비지 않는다)
}
```

**지켜야 할 것 네 가지**

1. `drawCharacter` / `drawProp` 의 **인자 모양을 바꾸지 않는다**
2. 캐릭터는 **발이 `(x, y)`**, 규격 32×48
3. 포즈 **여섯 개를 전부** 구현한다 (`idle · walk · type · carry · wait · reject`)
4. **이름표·명찰·말풍선은 계속 코드로** 그린다 — 글자는 그림에 넣지 않는다

그리고 CLAUDE.md 절대 규칙 6 — **출처·라이선스를 `web/assets/CREDITS.md` 에 남기고 파일로 담는다.**
생성형으로 만든 것도 *"모델 · 생성 날짜 · 사용한 프롬프트"* 를 적어 둔다.

## 8. 검수 체크리스트

- [ ] 바닥 격자 위에 얹었을 때 **마름모가 타일과 맞는가** (30°)
- [ ] 배경이 완전히 투명한가 — 반투명 찌꺼기가 없는가
- [ ] 면 세 개의 밝기 차가 보이는가
- [ ] **글자가 하나도 없는가**
- [ ] 우리 팔레트 안에 있는가 — 상태색(앰버·빨강·초록)을 쓰지 않았는가
- [ ] 그림자·블룸·부드러운 조명이 안 들어갔는가
- [ ] 10장을 나란히 놓았을 때 **같은 그림체로 보이는가**
- [ ] `s = 0.5` 로 줄였을 때도 형태가 읽히는가
- [ ] 캐릭터: 6포즈의 **키와 발 높이가 같은가** (다르면 걸을 때 덜컥거린다)

| **부르지 않은 글자** | 알 수 없는 문자·라벨이 붙음 | NO TEXT 를 대문자로, 블록 끝에 한 번 더. 나오면 그 장은 버린다 |
| **부드러운 조명·그림자** | 3D 렌더처럼 뽀얘짐 | *"no soft lighting, no ambient occlusion, no bloom, no cast shadow"* |
| **원근이 들어간다** | 뒤쪽이 좁아짐 | *"strictly orthographic"* 를 앞쪽에 배치 |
| **장마다 그림체가 다르다** | 10명이 남남처럼 보임 | 기준 장 하나 완성 → 편집 엔드포인트로 나머지 |
| **캐릭터 키가 제각각** | 걸을 때 덜컥거림 | 6포즈를 한 장에 같은 baseline 으로 요청 |
| **크기가 세 가지뿐** | 원하는 비율이 안 나옴 | 넉넉히 뽑고 잘라낸다 (6.2) |
| **투명이 반투명으로** | 가장자리에 흐린 띠 | API `background="transparent"` 사용. 화면 경로면 마젠타 대안(5.7) |
